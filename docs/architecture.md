# 架构与实现说明

## 设计输入

设计文件为 Pixso `Finess App UI_v1`，读取页面为 `xd page`（`0:1`）。设计包含 32 个宽 375 的界面画板，涵盖输入状态、长页面和个人中心分栏。原图位于 `reference/`；所有画板与图片节点 ID 位于 [design_manifest.json](design_manifest.json)。

应用按实际页面与状态组织代码：输入状态由系统键盘控制；首页和食谱的长短版本共享滚动页面；个人中心使用三个分栏。UI 是可操作的 Flutter Widget，不以整张设计截图作为界面背景。

## 分层与依赖方向

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 入口 | `lib/main.dart` | 初始化 Flutter、加载持久状态、恢复 Android 相册中断结果 |
| 应用 | `lib/app.dart` | 命名路由、主导航、状态订阅、全局存储失败提示 |
| 界面 | `lib/features/` | 页面布局、表单校验、临时交互状态 |
| 共享 UI | `lib/shared/`、`lib/core/` | 视觉规范、通用组件与绘图 |
| 状态与数据 | `lib/data/app_state.dart`、`catalog.dart` | 收藏、档案、日志、课程/食谱数据 |
| 平台适配 | `storage.dart`、`photo_service.dart` | 本地偏好和原生相册 |

Widget 将业务修改提交给 `AppState`，由状态对象通知已订阅的界面。`AppState` 只依赖抽象的 `AppStorage`，因此可用内存存储验证逻辑。没有引入额外路由、状态管理或图表框架。

## 状态生命周期

1. 启动时读取 `ardent_state_v1` JSON，恢复登录演示状态、资料、目标、收藏和日志。
2. 对缺失字段使用默认值；非法存储类型回退到初始状态；旧日志中已不存在的食谱 ID 会被过滤。
3. `update` 同步修改内存并刷新界面，再将当时的快照加入串行写入队列。
4. 写入失败保留内存状态并展示提示，后续成功写入会清除提示。
5. 退出只清除演示登录状态，保留本机资料和记录。

日期使用本机日期。周从周日开始；记录键为 `YYYY-MM-DD:条目ID`。同日同一食谱只记录一次，同日同一课程只完成一次，这是当前演示版的去重约定，并非支持多份或重复组数的饮食日志。

## 路由

| 路由 | 内容 |
| --- | --- |
| `/` | 三屏滑动引导 |
| `/login`、`/signup` | 演示登录、注册 |
| `/forgot`、`/verify` | 找回入口与演示验证 |
| `/goal`、`/details`、`/preferences` | 初次设置三步 |
| `/home` | 训练主栏 |
| `/workout`、`/workouts` | 选中课程、按难度浏览 |
| `/player` | 动作计时 |
| `/tips`、`/article` | 内容列表与阅读 |
| `/diet`、`/meals` | 推荐与按餐次浏览 |
| `/recipe`、`/recipe/expanded` | 简洁食谱、包含图片及步骤的完整食谱 |

当前选中的课程和食谱保存于内存状态，详情页和播放器读取同一对象。底部导航使用 `IndexedStack` 保留主栏位置。路由供本地演示导航使用，没有真实服务端鉴权。

## 计时与相册

训练播放器的准备阶段为 8 秒，随后进入课程动作列表。支持暂停、恢复和跳过动作，完成后写入日期日志。播放器离开前台时自动暂停，退出页面时取消计时器。课程分钟、营养值与消耗为演示目录数据，不构成实时测量。

相册使用系统选择器，选图时限制宽度和质量，读取后再检查大小。图片以 Base64 保存到本机偏好存储，避免临时路径失效，支持 Android 相册流程被系统中断后的恢复。个人图片最多 5 张、每张 500 KB；大规模照片应改用应用文件目录及数据库索引。

Android Release 构建在 `android/app/proguard-rules.pro` 保留本地存储的 Pigeon JNI 接口及其参数类型，避免压缩改名后读取与写入失败。此规则仅针对存储插件包，其余代码仍按正常规则优化。

## 验证策略

- 状态测试验证持久化恢复、连续写入顺序、收藏切换、日期隔离、重复记录、防止非法数据导致追踪崩溃及保存失败恢复。
- 页面测试遍历全部路由，在 375 和 320 宽度检查布局异常，并验证登录校验与计时暂停/完成行为。
- Android 集成测试执行新账号设置、训练完成、食谱步骤与记录、收藏、资料编辑、本地真实存储恢复以及底部导航，生成全部页面截图。
- [test_report.json](test_report.json) 保存最近一次集成测试结果；截图说明见 [screenshots/README.md](screenshots/README.md)。

## 后续接入位置

真实账号服务可在 `auth.dart` 的提交入口接入独立认证仓库，使用安全存储保存令牌，并为路由增加鉴权。课程和食谱可从 `catalog.dart` 的静态目录迁移到 API 仓库；收藏与日志保留现有业务入口。视频资源准备后，可将计时图片区与烹饪指南替换为独立媒体组件。推送与多语言需要独立的系统通知和本地化实现；当前开关与语言选项不宣称提供这些服务。
